# Employee Attendance & Analytics API

The backend for a small HR attendance system. Employees punch in and out, HR corrects records, and analytics
(monthly summaries, department summary, late leaderboard, daily trend) run as MongoDB aggregation pipelines.
All application code is in `app/main.py`. The contract is `openapi.yaml`, and the stored data is described in `DATA_MODEL.md`.

## Requirements
- Python 3.11+
- MongoDB 6.0+ (uses `$densify`, `$setWindowFields`, `$documents`), local or Atlas

## Install and run
```bash
python -m venv .venv && source .venv/bin/activate        # Windows: .venv\Scripts\activate
pip install -r requirements.txt
cp .env.example .env                                     # or export the variables below
uvicorn app.main:app --port 8000
```

| Variable | Meaning |
|---|---|
| `MONGO_URI` | MongoDB connection string (required) |
| `MONGO_DB` | Database name (required) |

Real environment variables override `.env`. The app refuses to start if either variable is missing. Indexes are created
idempotently at startup. If MongoDB is unreachable at startup, the app still starts, `/health` returns 503, and indexes are
created once MongoDB answers.

Seed the nine sample documents: `python sample_seed.py`.
API docs: `http://localhost:8000/docs` (generated by FastAPI) and `openapi.yaml` (the contract).

## Tests
```bash
pytest -q
```
The suite needs a real MongoDB at `TEST_MONGO_URI` (default `mongodb://localhost:27017`). It creates and drops a throwaway
database. Without a server the integration tests are skipped and only the pure rule tests in `tests/test_rules.py` run.

| File | Covers |
|---|---|
| `tests/test_rules.py` | R1-R5 helpers: grace boundary, overnight dates, truncation, overtime 29/30, half-up work hours, rounded half-day boundary |
| `tests/test_api.py` | employees, punch-in/out, list, PATCH, validation (seconds/float/string/bool timestamps), health 503 |
| `tests/test_concurrency.py` | parallel creates, punch-ins, punch-outs, regularizations (no lost history) |
| `tests/test_analytics.py` | hand-computed expectations: no-log employees, joiners, ties at cutoff, weekends, LEAVE/ABSENT, empty ranges |
| `tests/test_explain.py` | 100,000-record dataset: every explain case has `IXSCAN` and no `COLLSCAN` |

## Design notes
- **Instants:** epoch ms in the API, BSON UTC datetimes in MongoDB, truncated to whole seconds (R1). The client is
  `tz_aware=True`, so no naive datetimes leak in.
- **Concurrency:** the unique `(emp_code, date)` index makes punch-in safe. Punch-out uses a conditional update on
  `punch_out: null`. PATCH uses an optimistic guard plus `$set` and `$push` in one update, and retries when it loses a race.
- **Analytics:** pipeline builders are shared by the endpoints and `/admin/explain/{endpoint}`, so explain runs exactly
  the production query. Rounding is half-up via `Decimal128` (MongoDB's `$round` is half-to-even).
- **Errors:** database failures return 503 `{"detail": "database unavailable"}`. Details are logged, never returned.
- See `REVIEW.md` (starter defects) and `DECISIONS.md` (indexes, races, ties, headcount, scaling).

## Interpretations and limitations
- The trend range limit of 92 days counts both ends inclusively, so a full quarter (e.g. Jul 1 - Sep 30) is allowed.
- Logs dated before an employee's `joined_on` are not filtered out. Stored data is treated as authoritative. The department
  summary and trend only include employees who have joined by the period end.
- A PATCH that still loses the race after 5 attempts returns 409 (the contract allows this).
